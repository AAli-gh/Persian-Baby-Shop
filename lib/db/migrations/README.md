# Migrations

Schema history for `@workspace/db`, generated by drizzle-kit from
`src/schema/index.ts`.

- `pnpm --filter @workspace/db run generate` — write a new migration after
  changing the schema.
- `pnpm --filter @workspace/db run migrate` — apply pending migrations.
- `pnpm --filter @workspace/db run push` — dev-only shortcut that diffs the
  schema straight onto the database without recording history.

## Baselining an existing database

`0000_*.sql` is the baseline: it creates every table as the schema stood when
migrations were introduced, so it only runs cleanly on an empty database. A
database that was previously created with `drizzle-kit push` already has those
tables, and `migrate` would fail on the first `CREATE TABLE`. Baseline it once
instead:

```sql
CREATE SCHEMA IF NOT EXISTS drizzle;
CREATE TABLE IF NOT EXISTS drizzle.__drizzle_migrations (
  id SERIAL PRIMARY KEY,
  hash text NOT NULL,
  created_at bigint
);
-- hash/created_at come from migrations/meta/_journal.json for 0000_*.sql
INSERT INTO drizzle.__drizzle_migrations (hash, created_at) VALUES ('<tag>', <when>);
```

The baseline also drops the unused `users.otp_code` / `users.otp_expires_at`
columns, which the OTP-era login flow left behind. On an already-pushed
database, remove them by hand:

```sql
ALTER TABLE users DROP COLUMN IF EXISTS otp_code;
ALTER TABLE users DROP COLUMN IF EXISTS otp_expires_at;
```
